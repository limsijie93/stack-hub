# stack-hub

A semantic layer over the best open-source agentic skills.

Good skills are scattered across a handful of excellent stacks, and they overlap badly.
Three repos ship the same idea under different names, each bound to its own tool, and no
one repo tells you which to reach for. stack-hub vendors them, distils them into
something comparable, and synthesises **one concept-level skill from N upstream skills** —
ported so it actually runs in Claude Code.

Not a fork. Not a mirror. The value is the synthesis and the record of why it was drawn
that way.

## Install

```bash
/plugin marketplace add limsijie93/stack-hub
/plugin install stack-hub-core     # earned its place
/plugin install stack-hub-lab      # on probation — run it alongside the upstream it draws on
```

## Layout

```
sources.yaml          upstream, pinned by commit
raw_source/               committed, pruned, read-only          (dev-only, never installs)
catalog/
  index.json          mechanical — derived, disposable
  exclusions.yaml     authored curation
  cards/              ~300-token distillations, one per skill
plugins/
  stack-hub-core/     promoted skills
  stack-hub-lab/      skills on probation
decisions/            why each concept boundary is drawn    (never ships)
.claude/skills/       repo-local dev tools                  (never ships)
scripts/sync-vendor.mjs
```

## Why it is built this way

Four facts about the corpus drove every structural decision.

**The corpus cannot be read live.** The three target stacks hold 150 `SKILL.md` files,
~790K tokens; gstack alone averages 42 KB per skill. Anything reasoning across upstream
must work from a pre-digested catalog, which is why `catalog/cards/` exists. Measured on
the two sources vendored today:

| | size | tokens |
|---|---|---|
| `raw_source/` corpus | 648 KB | ~166,000 — cannot be read live |
| `catalog/cards/` (all 67) | 101 KB | **~26,000 — fits in context at once** |

A 6.4x compression, which is what lets the forge skill cluster on the whole active
corpus in a single pass instead of sampling it.

**Descriptions cluster wrongly.** `mattpocock/grilling` and `pstack/interrogate` describe
themselves almost identically — adversarial, challenge this, stress-test. One is a
sequential human dialogue about a *plan*; the other fans models over a *diff* with no
human present. Only reading the bodies reveals it. Cards therefore record `mechanism`,
`subject` and `human_in_loop`, never the upstream pitch. See
[`decisions/0001`](decisions/0001-fan-out-review.md).

**Vendored skills are not drop-in runnable.** `interrogate` reads
`~/.cursor/rules/pstack-models.mdc` and hardcodes cross-vendor model slugs; gstack uses
`{{PREAMBLE}}` placeholders and frontmatter keys Claude Code ignores. Porting is most of
the work, so every card lists the landmines and every skill must resolve them.

**Plugins are isolated.** The cache is flat per-plugin with independent versions and no
dependency mechanism, so no plugin can path into another's files. Hence `raw_source/` is
dev-only and every semantic skill is self-contained.

## Working on it

See [CONTRIBUTING.md](CONTRIBUTING.md) for the add-a-skill loop, the lab→core promotion
gate, and how drift detection works.

```bash
node scripts/sync-vendor.mjs             # fetch, prune, reindex, report drift
node scripts/sync-vendor.mjs --check     # no writes; exit 1 if a declared sha is stale
node scripts/sync-vendor.mjs --upstream  # look past the pin at upstream HEAD
```
