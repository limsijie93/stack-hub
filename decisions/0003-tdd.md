# 0003 — tdd

Date: 2026-08-30. Skill: `plugins/stack-hub-lab/skills/tdd/`.

## Cluster

The only remaining same-name, same-subject collision across the two vendors:

- `mattpocock/engineering/tdd@8fc0867` — `subject: codebase`, human in the loop
- `pstack/tdd@7d923bd` — `subject: codebase`, no human

Unlike `grilling`/`interrogate`, the shared name is honest here: both are about writing tests.

## The distinction

They are **complementary halves, not competitors**, which is what makes this the cleanest
merge in the corpus:

| | mattpocock | pstack |
|---|---|---|
| Question answered | what makes a test worth keeping | whether to write one at all |
| Core content | seams, three anti-patterns, loop rules | skip conditions, "bad test" definition |
| Posture | discipline for doing it right | discipline for not doing it |

Neither is complete alone. mattpocock's will happily have you write an expensive test at a
correct seam; pstack's will stop you writing it but has little to say about the one you do
write. Merged, the skill answers "should this exist" before "where does it go", which is the
order the questions actually arrive in.

## What the synthesis adds

The **ordering**. Both upstreams bury their strongest rule in the middle; joined, the skill
has a spine: *is it worth writing → where does it go → what makes it good → the loop*. Two
rules that were incidental upstream become gates:

- **"Never skip silently"** (pstack) is placed immediately after the skip conditions, so
  deciding against a test is a stated decision rather than an absence.
- **"If no correct seam exists, that is the finding"** (mattpocock, from its regression-test
  section) is lifted next to the seam rule, where it does more work: it converts "I couldn't
  test it" from an excuse into a reportable architectural result.

## Composition with evidence-discipline

`evidence-discipline` (0002) already took pstack/tdd's "report the evidence, not the outcome"
and its failing-before/passing-after contract. `decisions/0002` explicitly parked "the bug-fix
workflow itself, which stays in a tdd skill" — this is that follow-through.

So this skill **defers rather than restates**: the Reporting section names the contract in one
paragraph and points at `evidence-discipline` for the rung ladder and the three verdicts. Both
live in `stack-hub-lab`, so they install together.

This is the first time two stack-hub skills compose. If it reads as a gap in use rather than a
clean seam, the fix is to inline a short version here — not to duplicate the ladder.

## Rejected

- **The `codebase-design` skill dependency.** mattpocock's tdd defers to it for the module /
  interface / depth / seam vocabulary. That skill is not in stack-hub, so the seam definition
  is inlined in one sentence instead. If a `design-vocabulary` skill is ever built, this should
  point at it and drop the inline.
- **Sidecar `tests.md` and `mocking.md`.** `raw_source/` does not ship; the minimum is inlined.
- **pstack's full seven-step workflow.** Step-by-step bug-fix sequencing is a debugging concern.
  `diagnosing-bugs` is the cluster that owns it, and it is still unbuilt.

## Open

- Overlap with a future `debugging` skill (`diagnosing-bugs` + `principle-fix-root-causes`).
  The boundary should be: debugging finds the cause, tdd locks it down. If they blur, the
  regression-test half belongs here and the loop-building half belongs there.
